Executive Summary

Following recent additions for freeze-proofing resilience, phone remote controls, and offline QR codes, frame rates experienced a severe regression from a locked 60 FPS down to ~28–30 FPS. In web graphics, whenever total frame time exceeds 16.67ms by even a fraction of a millisecond, display VSync cuts the rendered refresh rate in half to 30 FPS.

A deep audit identified 5 interacting compounding bottlenecks across GPU texture management, HUD DOM thrashing with CSS blur readbacks, fragment shader overwork, duplicate audio analysis, and synchronous I/O storms.

Root Cause Breakdown & Remedies

1. Non-Power-Of-Two (1536px) Canvas Resizing & Preload Stalls GPU Memory & Main Thread
Root Cause

Almost all crate images in the repository are native 2048x2048 (a Power-Of-Two). In an attempt to reduce VRAM, maxTextureSize was set to 1536. This forced downscaleImageIfNeeded() to synchronously draw every single 2048px image onto a 1536px 2D canvas on the main CPU thread. Worse, 1536 is NOT a power of two (1536 = 3 × 512). Because Three.js textures use MirroredRepeatWrapping and mipmaps, Three.js had to resize the canvas a second time during GPU upload. Additionally, preloadCrateAssets immediately queued 4 neighbor textures (2–5MB JPEGs each) during active playback.

Resolution Implemented

• Set maxTextureSize: 2048 in src/config.js so 2048px assets upload straight as native textures with zero CPU canvas redraw.
• If an image exceeds 2048px, it now snaps directly to the nearest POT (2048 or 1024).
• Added a 1.5s idle debounce to preloadCrateAssets and restricted background pre-warming to only 1 immediate neighbor so asset switches never stutter live rendering.

2. 60Hz DOM Layout Thrashing Over backdrop-filter Blurs Compositor & Style Layout
Root Cause

The live diagnostic HUD overlay (#hud-overlay) and preview cards were styled with backdrop-filter: blur(10px) directly over the WebGL canvas. In DiagnosticHud.update(), over 60 DOM elements had their .textContent, .style.width, and .className modified every single animation frame (60 times per second) without dirty-checking. Furthermore, 12 meter bars had CSS transitions (transition: width 0.05s) firing continuously, and the drop badge ran an infinite box-shadow keyframe animation. This forced the Chromium compositor to re-rasterize and re-run costly Gaussian blur passes over the entire screen on every frame.

Resolution Implemented

• Throttled HUD DOM modifications in src/hud.js to ~12Hz (85ms interval) while keeping the internal FPS counter sampling at full frequency.
• Added cached dirty-checking helpers (_setText, _setWidth, _setActive) using a WeakMap so unchanged DOM nodes are never touched.
• Removed backdrop-filter: blur and CSS width transitions from the HUD, added contain: layout style paint to isolate repaints, and ensured hidden preview cards use visibility: hidden so inactive cards consume zero GPU compositor memory.

3. Pass 2 Fragment Shader Overwork & Fractional DPI Supersampling GPU Fragment Fillrate
Root Cause

The rendering engine uses a 2-pass pipeline: Pass 1 renders the 3D Totem mesh, and Pass 2 executes fluid silhouette feedback across a full-screen ortho quad. In Pass 2, trigonometry (atan(p.y, p.x), cos, sin) and 3 texture lookups into previous feedback were being calculated on 100% of all screen pixels—even when the pixel was completely opaque (curr.a == 1.0). In World-Field mode (the default), 100% of the screen is opaque artwork, meaning all 3 feedback samples were calculated and immediately thrown away! On top of that, on 125% Windows DPI scaling, maxPixelRatio: 1.5 was forcing Pass 2 to render at 1.25x (56% more pixels) with unnecessary 4x MSAA antialiasing enabled.

Resolution Implemented

• Added an early-exit branch in src/three-engine.js: if curr.a >= 0.999, the shader skips the 3 texture fetches and trigonometric calculations entirely.
• Replaced trigonometric normalizer vec2(cos(a), sin(a)) with instantaneous p / r, and deferred atan so it only runs when the radial gobo style is engaged.
• Initialized WebGL renderer with alpha: false, antialias: false, depth: false, stencil: false for the full-screen Pass 2 quad, locked maxPixelRatio: 1.0, and culled the CPU stardust loop in opaque World-Field mode.

4. Redundant Dual Audio & BPM Analysis in Pulse Mode Web Audio & CPU Loops
Root Cause

When Manual BPM Pulse Mode was active (which was toggled ON in the live session), AudioEngine.update() was still running live microphone FFT calculations, kicking off BpmDetector.update() (which ran 2 extra bandpass FFTs and runHarmonicClustering with ~81,000 nested candidate loop iterations every 80ms), allocating new arrays via .filter(), and scanning 360-element rolling arrays—only to overwrite the result at the end with _applySyntheticPulse().

Resolution Implemented

• Added an immediate fast-path return at the top of AudioEngine.update() when pulseMode is active, bypassing all microphone FFTs and detector loops.
• Replaced per-frame .filter() calls in src/audio.js and src/bpm-detector.js with in-place while (...) shift() to eliminate garbage collection micro-pauses.
• Made BPM harmonic clustering strictly event-driven (only executing when a kick or snare onset occurs) and reused a pre-allocated Float32Array score buffer.

5. Synchronous localStorage & Heartbeat Echo Storms Main Thread I/O & SSE
Root Cause

Whenever a slider (audio sensitivity or wave spread) was adjusted from the phone, executeRemoteControl() triggered synchronous localStorage.setItem() and an immediate HTTP POST /api/action heartbeat on every 60ms drag event. The backend (serve.py) then broadcast that heartbeat right back over SSE to the laptop, and the laptop continued polling /api/state every 1.8s even while SSE was already connected. Furthermore, serve.py was rewriting the 1,550-line assets/manifest.json to disk every 10 seconds.

Resolution Implemented

• Debounced saveSessionState() by 800ms so rapid phone touch drags never cause synchronous disk write blocking on the rendering thread.
• Removed redundant per-action heartbeat POSTs and paused HTTP polling when SSE is active and healthy.
• Optimized serve.py to cache local IP queries for 30s, drop SSE broadcast echoes for routine heartbeats, and only write manifest.json when the asset folder structure actually changes.
